# Фреймворк разработки E2E-тестов

Проект представляет собой самостоятельный фреймворк для организации разработки E2E UI-тестов на Playwright Test и TypeScript. Он задаёт единый подход к описанию Test Case (TC), Action (`AA-`), исследованию интерфейса, хранению селекторов, реализации тестов и диагностике результатов. Фреймворк предназначен для подключения к тестируемому проекту и адаптации под его фактическую структуру, окружения и бизнес-сценарии.

В состав фреймворка входят команды OpenCode, инструкции, шаблоны и Python-скрипты. Команда `/init-project` собирает контекст конкретного проекта. Команды `/create-aa`, `/create-tc`, `/edit-aa` и `/edit-tc` управляют созданием и изменением документации. Команды `/research-tc`, `/implement-tc` и `/run-tc` обеспечивают разработку отдельных сценариев. Команда `/update-index` поддерживает актуальный индекс существующих TC и Action.

Фреймворк обеспечивает независимость тестов, подготовку данных через UI (с явными исключениями, если TC указывает использовать готовую сущность), безопасную работу с утверждённой документацией и восстановление прерванного выполнения задачи.

Для использования:

1. Создайте `.env.dev` с базовыми настройками подключения к системе.
2. Откройте `opencode` и выполните команду `/init-project` — она соберёт особенности проекта (архитектура приложения, доступность API для данных, готовые сущности, именование переменных окружения, расположение документации, используемый инструментарий) в раздел «Контекст проекта» файла `AGENTS.md`.
3. Установите и настройте технические компоненты проекта (зависимости, Playwright Test, LSP) по фактическим потребностям вашего стека.
4. Создавайте тесты.
5. Скопируйте файл run-tests.sh в папку проекта разработки, для которого создаются тесты. При запуске передавайте параметром путь к проекту с тестами. Добавьте в AGENTS.md этого проекта следующий промпт:
***
# Инструкция по верификации кода
Вся проверка работоспособности кода выполняется исключительно через запуск готового тестового скрипта. Тесты находятся в изолированной директории, доступа к которой у тебя нет.
## Как запускать тесты
Выполняй команду строго из корня текущего проекта:
```bash
./run-tests.sh ~/project/tests
```
## Правила работы
1. Не пытайся искать или читать исходный код тестов.
2. Твоя цель — добиться вывода `PASSED` от скрипта. 
3. Если тесты упали, анализируй ошибку в консольном выводе (stdout/stderr), исправляй реализацию и запускай скрипт заново.
