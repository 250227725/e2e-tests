# Создание проектной документации

## Область применения

Инструкция применяется только командами `/create-aa` и `/create-tc`.

Она разрешает создать один новый документ, но не разрешает изменять, перезаписывать, перемещать или удалять существующую документацию.

После сохранения новый документ считается утверждённым.

## Интерактивный режим

Собирай требования в диалоге.

- Задавай по одному вопросу за сообщение.
- Не повторяй вопросы, на которые пользователь уже ответил.
- Учитывай начальное описание из аргументов команды и сведения текущего диалога.
- Задавай только вопросы, необходимые для однозначного заполнения документа.
- Не придумывай требования, параметры, шаги, результаты и зависимости.
- Не выбирай наиболее вероятную трактовку.
- При полезности предложи конкретную формулировку, но запроси решение пользователя.
- Не переходи к согласованию, пока обязательные сведения не определены.

## Проверка существующих документов

До выбора идентификатора:

1. Получи список существующих документов соответствующего типа.
2. Проверь уникальность идентификатора и целевого пути.
3. Проверь отсутствие существующего документа с тем же смыслом.
4. Открывай только документы, необходимые для этой проверки.

При создании TC открой полные документы только тех AA, которые пользователь указал как зависимости.

## Формирование Atomic Action

В разделе `Варианты успешного результата` перечисляй только наблюдаемые положительные состояния, каждое из которых подтверждает успешное выполнение AA.

- Не описывай отрицательные результаты, ошибки, таймауты и состояние «другое».
- Каждый перечисленный вариант является достаточным условием успешности действия.
- Любой исход, не совпавший ни с одним перечисленным вариантом, считается неуспешным выполнением AA.
- Если вызывающему TC необходимо знать, какой именно успешный вариант достигнут, явно опиши это значение в разделе `Выходные данные`.
- Если допустим только один успешный результат, укажи один элемент списка.

## Подготовка проекта

После завершения опроса:

1. Проверь полноту и внутреннюю согласованность документа.
2. Определи идентификатор и целевой путь.
3. Покажи целевой путь.
4. Покажи полный текст документа.
5. Запроси явное подтверждение сохранения именно этой редакции.

До подтверждения не создавай файл.

## Согласование

Пользователь может подтвердить редакцию, потребовать изменения, дополнить требования или отменить создание.

После любого изменения снова покажи полный текст документа и запроси подтверждение.

Подтверждение предыдущей редакции не распространяется на изменённую редакцию.

## Сохранение

Непосредственно перед записью повторно проверь:

- уникальность идентификатора;
- отсутствие файла по целевому пути;
- наличие обязательных разделов;
- соответствие идентификатора заголовку, разделу `Код` и имени файла;
- существование всех указанных ссылок на другие документы.

Создай только один согласованный файл.

Не создавай автоматически:

- спецификацию селекторов;
- тестовый код;
- другой TC или AA;
- запись в `test-dependencies.json`;
- сопутствующие файлы.

Если целевой файл появился во время согласования, не перезаписывай его. Верни `BLOCKED` и предложи новый идентификатор.

## Завершение

После сохранения сообщи:

- созданный идентификатор;
- путь файла;
- что документ сохранён и теперь считается утверждённым.

Если пользователь отменил создание, не изменяй файлы проекта.
