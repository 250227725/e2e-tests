# Тестовые данные и окружение

## Учётная запись

- Если TC определяет конкретную учётную запись, используй именно её.
- Иначе используй базовую учётную запись из конфигурации окружения.
- Получай значения из существующих переменных окружения.
- Не угадывай имена переменных.
- Не копируй секреты в код, логи, отчёты и ответы.
- При отсутствии обязательной переменной заверши выполнение с понятной ошибкой.

## Бизнес-сущности

Все бизнес-сущности, необходимые для выполнения TC, создаются текущим тестом через UI, если TC явно не указывает использовать готовую существующую сущность (см. группу тестовых данных TC, ссылающуюся на неё). Такое явное указание не оспаривается — оно уже согласованное решение, а не нарушение правила.

Запрещено, если иное прямо не указано в TC:

- использовать существующую бизнес-сущность как предусловие;
- искать подходящую существующую запись;
- использовать сущность другого теста;
- зависеть от данных предыдущего запуска.

Подготовка данных через API возможна только если это явно разрешено в разделе «Контекст проекта» файла `AGENTS.md`. По умолчанию — только через UI.

Очистка созданных данных не выполняется, если TC не требует обратного.

## Идентификатор запуска

Для каждого теста один раз сформируй уникальный `runId`.

- `runId` должен содержать timestamp.
- При возможном параллельном запуске добавь компонент, исключающий совпадение между worker-процессами.
- Используй один `runId` во всех связанных значениях текущего теста.
- Тестовые значения должны оставаться читаемыми и диагностируемыми.

## Контекст теста

Для каждого теста создаётся отдельный типизированный контекст.

- Контекст не является глобальным.
- Контекст не разделяется между тестами.
- Имена полей отражают бизнес-смысл.
- Обязательные значения проверяются до использования.
- Чувствительные данные не выводятся в отчёты.
- В контекст попадают только значения, переданные через UI, сгенерированные тестом, прочитанные из UI или подтверждённые выполнением действия.
- Не придумывай скрытые системные идентификаторы.

Пример структуры является локальным решением теста, а не универсальным контрактом проекта.

## Генерируемые группы тестовых данных

Для группы тестовых данных TC, помеченной как генерируемая, реализуй значения по требованиям к формату, указанным в TC. Способ генерации не документируется в TC — выбирается на этапе реализации:

- если в проекте подключён Faker (или аналог, зафиксированный в «Контексте проекта» `AGENTS.md`) — используй его;
- если генератор не подключён — реализуй генерацию вручную по описанным в TC правилам, без добавления новой зависимости самостоятельно.
