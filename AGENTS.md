# AGENTS.md

## Назначение

Репозиторий предназначен для разработки независимых E2E UI-тестов веб-приложения на Playwright Test и TypeScript.

Работа ведётся по утверждённым спецификациям Test Case (TC) и Atomic Action (AA). Агент реализует требования, исследует фактический интерфейс через Playwright MCP, выбирает устойчивые локаторы, выявляет неоднозначности до реализации и сохраняет стабильность существующих тестов.

## Постоянные ограничения

- Приложение не является SPA; переходы могут приводить к полной загрузке страницы.
- Взаимодействие с системой выполняется только через веб-интерфейс.
- API для подготовки тестовых данных не используется.
- Для TC может быть определена конкретная учётная запись; иначе используется базовая учётная запись окружения.
- Все остальные необходимые бизнес-сущности создаются текущим тестом через UI.
- Существующие бизнес-сущности не используются как предусловия.
- Тесты не зависят от порядка выполнения, общего состояния и данных других тестов.
- Очистка созданных данных не требуется, если обратное не указано в TC.
- Тесты выполняются локально.
- Архитектура не должна препятствовать будущему параллельному выполнению.

## Источники истины

- Проверяемое бизнес-условие определяется TC.
- Контракт атомарного действия определяется AA.
- Связь `TC → AA` определяется разделом `Зависимости` соответствующего TC.
- Фактическое устройство интерфейса определяется исследованием через Playwright MCP.
- Спецификация селекторов фиксирует результат предыдущего исследования, но не заменяет проверку реального интерфейса.
- TypeScript-код описывает текущую реализацию, но не изменяет смысл TC или AA.

При противоречии между TC и AA агент возвращает `BLOCKED` и не выбирает трактовку самостоятельно. Фактическое поведение приложения не отменяет утверждённое требование.

## Проектная документация

Все существующие TC, AA и selector-спецификации считаются утверждёнными. Selector-файлы хранятся рядом с документом как `<DOCUMENT-ID>.selectors.md`.

Агент не изменяет, не перезаписывает, не перемещает и не удаляет утверждённую документацию.

Создание новой спецификации разрешено только командами:

- `/create-aa`;
- `/create-tc`.

Новый документ сохраняется только после согласования полного текста с пользователем. После сохранения он считается утверждённым.

Если существующая документация требует изменения, агент:

1. останавливает выполнение в точке, после которой изменение обязательно;
2. возвращает `BLOCKED`;
3. описывает проблему;
4. предлагает готовую редакцию или точный diff;
5. указывает затронутые документы и разделы.

Обсуждение в диалоге не заменяет утверждённую документацию.

## Окружение и секреты

- Стартовый URL и данные учётных записей берутся из существующей конфигурации окружения.
- Имена переменных определяются по фактическому проекту и не угадываются.
- Секреты не выводятся в ответы, логи и отчёты и не копируются в код.
- файлы `.env.*` не добавляются в коммиты.
- Значения учётных записей не изменяются без явной команды.
- Отсутствие обязательной переменной приводит к понятной ошибке.

## Безопасность изменений

Перед изменением файлов проверь текущее состояние репозитория.

Запрещено:

- перезаписывать несвязанные изменения пользователя;
- откатывать или удалять файлы вне текущей задачи;
- выполнять destructive-команды Git;
- создавать commit, выполнять push или изменять историю без явной команды;
- форматировать весь проект, если задача затрагивает отдельные файлы;
- изменять код тестируемого приложения;
- маскировать дефект приложения изменением ожиданий;
- отключать или ослаблять проверки и существующие тесты;
- добавлять retries или увеличивать timeout без диагностики;
- заявлять о проверке, которая фактически не запускалась;
- выдавать результат предыдущей сессии за результат текущего запуска.

Изменения ограничиваются минимальным набором необходимых файлов.

## Статусы

Не смешивай три разных типа значений.

**Статус работы агента:**

- `DONE` — порученная работа завершена;
- `BLOCKED` — требуется решение пользователя или изменение документации;
- `FAILED` — работа не завершена по технической причине.

**Результат теста:** `PASSED | FAILED | NOT_RUN`.

**Решение для TC полного запуска:** `RUN | BLOCKED`.

**Итог полного запуска:** `PASSED | COMPLETED_WITH_ISSUES | CONFIGURATION_ERROR | SCRIPT_ERROR`.

Работа может завершиться `DONE` при результате теста `FAILED`, если корректный тест выявил дефект приложения.

## Команды OpenCode

### Создание документации

- `/create-aa [описание]` — интерактивно создать и согласовать новый AA.
- `/create-tc [описание]` — интерактивно создать и согласовать новый TC.

### Работа с одним TC

- `/research-tc <TC-ID>` — исследовать TC через MCP без изменения кода.
- `/implement-tc <TC-ID>` — исследовать, реализовать и проверить один TC.
- `/run-tc <TC-ID>` — изолированно запустить один реализованный TC.

## Подключение контекста

Не загружай все правила и документы заранее.

Команды сами подключают необходимые файлы из `.opencode/instructions/` и `.opencode/templates/`. При работе без команды прочитай только инструкцию, относящуюся к текущей задаче:

- создание документации — `documentation-authoring.md`;
- реализация TC — `test-development.md`;
- данные и окружение — `test-data-and-environment.md`;
- Playwright-код — `playwright-implementation.md`;
- интерфейс и локаторы — `selector-research.md`;
- диагностика — `diagnostics.md`;

Для одного TC открывай только целевой TC, AA из его раздела `Зависимости`, связанные спецификации селекторов и непосредственно затронутый код. 

## Владельцы правил

- постоянные ограничения и запреты — `AGENTS.md`;
- создание TC и AA — `documentation-authoring.md`;
- процесс реализации TC — `test-development.md`;
- данные и контекст теста — `test-data-and-environment.md`;
- Playwright-код — `playwright-implementation.md`;
- локаторы и селекторы — `selector-research.md`;
- ошибки, статусы и отчёты — `diagnostics.md`;
- создание и проверка новых TC/AA — `.opencode/scripts/document_authoring.py`;
- форма документа или отчёта — соответствующий файл в `.opencode/templates/`.

Команды определяют только точку входа, подключаемые материалы, границы операции и ожидаемый результат. Они не должны дублировать тематические правила.
